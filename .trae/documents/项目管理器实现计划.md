# 项目管理器（GitHub + 本地）实现计划

## Context

用户需要一个 Python 桌面 GUI 应用，统一管理本地任务与本地 git 仓库，并集成 GitHub（Issues / PR / 仓库信息，支持读写）。项目目录为空，从零搭建。用户已确认：桌面 GUI、功能全覆盖（任务看板 + 仓库管理 + GitHub 面板）、Python 技术栈。

## 技术选型

- **GUI**: PySide6（表格/看板/线程能力开箱即用；老设备可设 `QT_OPENGL=software` 回退）
- **git 读取**: GitPython >= 3.1.44（只读状态不触网；fetch 为可选操作，失败降级提示）
- **GitHub API**: PyGithub >= 2.3（PAT 认证）
- **本地数据**: sqlite3 标准库，数据库放 `%LOCALAPPDATA%\ProjectManager\pm.db`（QStandardPaths 定位）
- **并发**: QThreadPool + QRunnable，所有 GitHub/扫描/fetch 进线程池，信号回传

│   │   ├── workers.py       # FunctionWorker(QRunnable) + WorkerSignals + run_async
│   │   └── settings.py      # SettingsStore：settings 表读写

│   │   └── repo.py          # @dataclass LocalRepo / RepoStatus
│   ├── services/            # 不 import PySide6，可单测
│   │   ├── task_service.py  # 任务 CRUD（UI 线程直接调，短连接）
│   │   ├── repo_service.py  # 扫描根目录/状态/提交历史/分支/fetch
│   │   ├── github_service.py# PyGithub 封装（阻塞式，worker 调用）
│   │   └── sync_service.py  # Issue <-> Task 双向同步
│   └── ui/

分层规则：UI 只调 services；跨 Tab 通信走信号。

## 数据表

- `tasks`: id, title, description, status(todo/doing/done), priority(high/medium/low), due_date, tags(逗号分隔), repo_id→repos, issue_number, issue_url, synced_at, created_at, updated_at
- `repos`: id, path(UNIQUE), name, remote_url, owner_repo(打通 Tab1/Tab3), added_at, last_scanned_at
- `settings`: key/value（github_token / scan_root / merge_method）

关键设计：repos 表存 `owner_repo`，任务推送 Issue、仓库跳转 GitHub 面板都从这里取目标。PAT 明文存本地（设置页加 fine-grained token 建议提示）。

## 核心功能

### Tab1 任务看板
- 三列（待办/进行中/已完成）QGroupBox + QListWidget，TaskCardWidget 渲染（标题加粗、优先级色点、截止日期、issue 链接样式）
- 交互：**阶段 1 用按钮+右键菜单移动（20 行搞定），最后阶段再加跨列拖拽**（自定义 QMimeData/QDrag，~150 行，与按钮走同一 `move_task` 入口）
- 工具栏：新建 / 拉取 Issues / 推送到 GitHub / 仓库过滤下拉

### Tab2 本地仓库
- `scan_root`: os.walk 限深 2-3 层，剪枝 .git/node_modules，发现 .git 即停
- 表格列：名称/路径/分支/dirty/ahead/behind；双击弹详情（提交历史+分支）
- 右键：资源管理器打开(os.startfile)/复制路径/在 GitHub 面板查看

### Tab3 GitHub 面板
- owner/repo 可编辑下拉（历史存 settings）+ 子 Tab：概览 / Issues / PR
- Issues：过滤 open/closed/all，创建/关闭/重开/评论（注意 PyGithub `get_issues` 混入 PR，需过滤 `pull_request`）
- PR：列表 + 详情对话框（merge 方法下拉 merge/squash/rebase + 合并/关闭）

### 同步
- `pull_issues`: 拉 open issues → 生成 todo 任务，`repo_id+issue_number` 已存在则跳过
- `push_task`: 任务创建 Issue（标签仅当远端存在同名标签），成功回写编号，防重复推送

## 实现阶段（每步可独立验证）

1. **脚手架**: venv + requirements + main.py 启动三空 Tab + 建库。验证：窗口弹出、pm.db 三表生成
2. **任务看板**: Task/TaskService/TaskCardWidget/TaskDialog + 三列渲染 + 移动/编辑/删除。验证：增删改查、移动跨列、重启持久化
3. **本地仓库**: RepoService 扫描/状态 + ReposTab 表格 + 详情对话框。验证：与 git status 结果一致、错误给中文提示不崩溃
4. **设置+GitHub 只读**: SettingsDialog + GithubTab 三子页（线程池加载，busy 禁按钮）。验证：无 token 匿名读公开仓库 → 配 token 读私有仓库，UI 不卡
5. **GitHub 写+同步**: issue 创建/关闭/重开/评论、PR merge/close、SyncService 接通看板。验证：**用一次性测试仓库**，网页核对每次写操作、重复拉取不重复建任务
6. **打磨**: 跨列拖拽、空状态文案、状态栏统一提示、可选 PyInstaller 打包

## 用户需准备

- Python 3.10+、系统 git
- GitHub PAT（推荐 fine-grained：Metadata 只读 + Issues/PR/Contents 读写，限仓库范围，短有效期）
- 一个本地 git 仓库父目录作扫描根目录
- 一个一次性测试仓库（阶段 5 验证写操作）

## 风险注意

- 中文路径（目录名"项目管理"）：全链路 pathlib + UTF-8
- 线程与 SQLite：每个 service 方法内 `with closing(get_connection())` 短连接
- busy 状态：异步期间禁用按钮防重复提交
- 沙箱可能拦截 fetch 网络操作：失败仅影响 ahead/behind 新鲜度，UI 提示降级

## 验证总纲

- 每阶段结束运行 `python main.py` 按上述验证点手工过一遍
- 服务层可用 `python -c` 直接调用快速自测（不依赖 UI）
- 阶段 5 所有写操作在测试仓库进行，网页 GitHub 交叉核对
