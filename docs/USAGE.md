# 使用指南

适用于 **v2.0.0**。所有路径以 Windows 默认安装为例，可按实际用户名替换。

## 1. 第一次启动

### 1.1 依赖与启动

- Python 3.10+、系统 git（`git --version` 可用）
- 双击 `启动项目管理器.bat`，或执行 `python main.py`
- 首次启动会在 `%LOCALAPPDATA%\ProjectManager\` 创建数据库与日志目录

### 1.2 配置 GitHub Token（可选）

匿名也能浏览公开仓库，但限流 60 次/小时，且不能新建 / 评论 / 关闭 Issue、合并 PR。

1. 打开「设置」→「GitHub 访问」
2. 填入 fine-grained token（推荐）或 classic token
3. 「保存」，状态变成「已加密保存」

推荐 fine-grained 权限：

| 权限 | 级别 | 用途 |
| --- | --- | --- |
| Metadata | 读 | 仓库基本信息 |
| Issues | 读写 | Issue 列表 / 新建 / 评论 / 关闭 |
| Pull requests | 读写 | PR 列表 / 合并 / 关闭 |

Token 存放位置见 [数据与备份](#7-数据备份与恢复)。

### 1.3 添加仓库扫描目录

1.「本地仓库」→「添加扫描目录」
2. 选择仓库的父目录；可重复添加多个
3. 扫描规则：最多递归 3 层，遇到 `.git` 即视为仓库并停止下探
4. 会自动跳过 `node_modules`、`.venv`、`dist`、`build` 等目录
5. 磁盘上已经不存在的仓库，下次扫描时会从数据库清理（关联任务保留，但解除仓库关联）

也可以在「设置」里批量管理扫描目录（添加 / 移除）。**移除扫描根目录只影响后续扫描**，已经入库且仍在磁盘上的仓库不会被自动删除。

## 2. 工作台

首页回答三个问题：今天做什么、这周做了多少、仓库是否健康。

- **待办 / 进行中 / 逾期 / 本周完成**：全部任务的实时统计
  - 逾期：未完成且截止日早于今天
  - 本周完成：最近 7 天（含今天）进入完成态的任务数
- **今日聚焦**：未完成、且「截止日 ≤ 今天」或「高优先级」的任务，最多 6 条
  - 排序：逾期优先 → 截止日近的优先 → 高优先级优先
  - 点击一行直接打开编辑
- **本周完成**：按天统计完成量，今天高亮；数据来自 `completed_at`
- **仓库健康**：仓库总数、有未提交改动的数量、落后远程的数量，并列出最需要留意的 3 个仓库
- **最近完成**：最后 3 个完成的任务

「刷新」会重新读取统计与仓库状态；仓库状态读取在后台完成。

## 3. 任务看板

三列：待办 / 进行中 / 已完成。

### 3.1 新建与编辑

- 顶部「＋ 新建任务」打开完整表单
- 列头的 `＋` 直接新建到该列
- 快速添加框输入标题后回车，默认进入「待办 / 中优先级」，并继承当前仓库筛选
- 双击卡片打开编辑；右键菜单也可以编辑

表单字段：

| 字段 | 说明 |
| --- | --- |
| 标题 | 必填 |
| 描述 | 推送为 Issue 时作为正文 |
| 状态 / 优先级 | 待办 / 进行中 / 已完成；高 / 中 / 低 |
| 截止日期 | 可留空；过期未完成会红色标记 |
| 标签 | 逗号分隔，例如 `bug,前端` |
| 关联仓库 | 决定能否推送 Issue、拉取时按哪个仓库去重 |

### 3.2 改变状态

- 拖拽卡片到另一列
- 卡片底部 `←` / `→`
- 右键「移到 …」

进入「已完成」时自动写入 `completed_at`；移出时清空，重新完成会更新时间。

### 3.3 搜索与筛选

- 搜索：标题、描述、标签（即时生效）
- 仓库 / 优先级 / 截止日 / 标签下拉
- 「重置」清空全部筛选
- 截止日筛选：今天到期 / 已逾期 / 未来 7 天 / 无截止日

排序固定为：高优先级 → 中 → 低；同优先级按截止日由近到远，无截止日排最后；再按新建时间倒序。

### 3.4 与 GitHub 同步

**拉取 Issues**

1. 在仓库筛选中选中**具体仓库**（不能是「全部仓库」）
2. 点「拉取 Issues」
3. 仓库的 open Issues 会变成任务：状态待办、优先级中、关联仓库、回写编号与链接
4. 同一仓库下已有相同 `issue_number` 的任务会跳过

**推送任务为 Issue**

1. 任务必须关联仓库，且尚未关联 Issue
2. 右键卡片 →「推送为 GitHub Issue」
3. 标签只有在远端仓库存在同名标签时才会附加
4. 成功后回写 Issue 编号与链接；重复推送会被拒绝

> 拉取 / 推送需要 Token。删除本地任务不会删除远端 Issue。

## 4. 本地仓库

### 4.1 状态列

| 列 | 含义 |
| --- | --- |
| 改动 | `git status --porcelain` 的行数（含未跟踪文件）；「干净」表示无改动 |
| 领先 | 本地比跟踪分支多的提交数，`↑N`；无跟踪分支显示 `—` |
| 落后 | 本地比跟踪分支少的提交数，`↓N`；无跟踪分支显示 `—` |
| 最近提交 | 当前 HEAD 的提交时间；悬停可看提交说明 |
| 路径 | 仓库绝对路径，悬停看完整路径与 GitHub 仓库名 |

全部仓库的状态在一次后台任务里读取，界面不会卡。

### 4.2 操作

右键仓库：

- 查看详情：分支列表 + 最近 50 条提交
- 在资源管理器中打开
- 在终端中打开：优先 Windows Terminal，回退 PowerShell 新窗口
- 在 VS Code 中打开：需要 `code` 命令在 PATH 中
- 拉取更新（`git pull --ff-only`）：有分叉或冲突时会失败并提示手动处理
- 复制路径
- 在 GitHub 页查看

工具栏：

- 刷新状态
- fetch 全部（只更新远程引用，不合并）
- 添加扫描目录

### 4.3 IDE 工作区同步

开启后，扫描完成与启动时会把所有仓库写入：

```
C:\Users\<你>\Desktop\日常维护.code-workspace
```

- `folders` 会按数据库重建（IDE 里手工加的目录会被覆盖）
- `settings` 等其它键保留
- 不想被改写：设置 → 取消「扫描仓库后同步 IDE 多根工作区文件」

## 5. GitHub

### 5.1 选择仓库

- 下拉里是本地仓库解析出的 `owner/repo`，以及最近加载过的历史
- 也可以手动输入 `owner/repo` 后回车或点「加载」
- 右上角状态：「已连接」表示有 Token；「匿名只读」表示只能读公开仓库

「加载」会拉取三类数据：仓库概览、open Issues、open PRs。

### 5.2 概览

- 描述、语言、Star/Fork、默认分支、Open Issues/PR、最近更新、链接
- 最近 3 个 Issue、最近 2 个 PR，可直接打开详情
- 快捷操作：新建 Issue、刷新仓库数据、在浏览器打开

### 5.3 Issues

- 按状态筛选（打开 / 已关闭 / 全部）并请求 GitHub
- 本地搜索框过滤标题、标签、作者、编号
- 双击或「详情」打开 Issue 详情：正文、评论流、评论输入框、关闭 / 重开、在浏览器打开
- 详情里 Ctrl+Enter 发送评论
- 「＋ 新建」创建 Issue；标签逗号分隔

### 5.4 Pull Requests

- 按状态筛选；双击或「详情 / 合并」打开
- 详情展示标题、分支、作者、状态、描述与链接
- 合并方式：合并（保留提交）/ 压缩合并 / 变基合并；默认值来自设置
- 只能操作 open 且未合并的 PR；也可以关闭 PR

### 5.5 限流与上限

- 匿名：60 次/小时；带 Token：5000 次/小时（GitHub 官方额度）
- 列表最多请求 100 条，避免一次耗尽配额
- Issue 评论最多展示 50 条
- 触发限流会提示稍后重试；不会自动无限退避

## 6. 设置

| 区块 | 内容 |
| --- | --- |
| GitHub 访问 | Token 状态、输入新 Token、显示 / 清除 |
| 外观与行为 | 主题（跟随系统 / 浅色 / 深色）、默认合并方式、工作区同步开关 |
| 仓库扫描目录 | 列表、添加目录、移除选中 |

Token 规则：

- 输入框留空 + 保存 = 保持原 Token 不变
- 输入新值 = 覆盖
- 点「清除」+ 保存 = 删除本地 Token
- 已保存的 Token 不会回显明文

主题切换立即生效；扫描目录变化会触发重新扫描。

## 7. 数据、备份与恢复

### 7.1 路径

| 内容 | 路径 |
| --- | --- |
| 数据库 | `%LOCALAPPDATA%\ProjectManager\pm.db` |
| 备份 | `%LOCALAPPDATA%\ProjectManager\backups\pm-YYYYMMDD-HHMMSS.db` |
| 日志 | `%LOCALAPPDATA%\ProjectManager\app.log`（1 MB × 3） |
| 单实例锁 | `%LOCALAPPDATA%\ProjectManager\app.lock` |
| Token | 项目根 `.env` 的 `GITHUB_TOKEN_DPAPI` |
| IDE 工作区 | `~/Desktop/日常维护.code-workspace` |

可用环境变量隔离数据（测试/演示）：

| 变量 | 作用 |
| --- | --- |
| `PM_DATA_DIR` | 覆盖数据目录（数据库、备份、日志、锁） |
| `PM_ENV_FILE` | 覆盖 `.env` 路径 |
| `PM_SYNC_WORKSPACE=0` | 禁止改写 IDE 工作区 |

### 7.2 自动备份

- schema 升级前：强制备份
- 日常启动：每天最多一次（距上次 ≥ 24 小时）
- 最多保留 10 份，按时间滚动

### 7.3 恢复

1. 完全退出应用
2. 关闭可能占用数据库的编辑器
3. 把目标备份复制为 `%LOCALAPPDATA%\ProjectManager\pm.db`
4. 重新启动

恢复会丢失备份时间点之后的数据；需要更细粒度请手动复制。

### 7.4 换机器 / 换 Windows 账户

- 数据库可以直接复制
- **Token 不能直接复制**：DPAPI 只能在同一 Windows 用户下解密，换账户/机器后请在设置里重新填写
- 旧机器上的 `.env` 若还有明文 Token，请删除旧副本

### 7.5 导出与日志

- 文件 → 导出任务 CSV…（`Ctrl+E`），UTF-8 BOM，Excel 可直接打开
- 文件 → 备份数据库：立即生成一份
- 工具 → 打开日志文件：排查异常
- 文件 → 打开数据目录

## 8. 常见问题

**Q：状态一直显示「读取中」/「刷新中」？**<br>
v2 已修复后台 Worker 被提前回收导致回调丢失的问题。若仍出现，查看 `app.log`，确认版本是 v2，并尝试重启应用。

**Q：提示 Token 无效或 401？**<br>
Token 过期或被撤销。到 GitHub 重新生成，在设置里覆盖保存。

**Q：Token 明明保存过，为什么变成未配置？**<br>
可能换了 Windows 账户 / 机器，DPAPI 无法解密。重新填写即可；日志里会有「Token 解密失败」告警。

**Q：匿名模式和 Token 模式有什么区别？**<br>
匿名只能读公开仓库，60 次/小时，不能写操作；Token 可读私有仓库，5000 次/小时，可写。

**Q：GitHub API 限流怎么办？**<br>
等额度重置，或配置 Token。列表最多 100 条，避免频繁刷新。

**Q：GitHub 请求 TLS 证书错误？**<br>
应用已通过 truststore 使用 Windows 系统证书链；仍失败时检查系统时间、代理与证书。

**Q：VS Code 打不开，提示找不到 code？**<br>
VS Code 安装时勾选「添加到 PATH」，或手动把 `code.cmd` 所在目录加入 PATH。

**Q：pull 失败，提示 not possible to fast-forward？**<br>
本地与远程分叉了。请到终端手动 `git pull --rebase` / 合并；管理器只做 ff-only，避免自动产生合并提交。

**Q：工作区文件被覆盖了？**<br>
这是设计的同步行为：`folders` 由仓库列表重建，`settings` 保留。可在设置里关闭同步。

**Q：删除磁盘上的仓库后，关联任务去哪了？**<br>
任务保留，`repo_id` 被置空（SQLite `ON DELETE SET NULL`），不会连带删除任务。

**Q：为什么迁移后看板还是空的？**<br>
迁移只升级结构，不会凭空生成任务。原来没有任务，升级后仍然是 0。

**Q：提示「项目管理器已经在运行」？**<br>
单实例锁生效。切回已打开的窗口；若上次异常退出，锁会在 30 秒后自动失效。

**Q：截图里的 `acme/*` 是真的仓库吗？**<br>
不是，是 `scripts/screenshots.py` 在临时目录生成的演示数据。
